# 标签规则

标签是跨文章查找主题的入口。分类继续表达文章所属专栏，标签不收录每一个 API、控件、命令、章节或文章形式。

## 当前主题

人工智能、AI Agent、软件工程、Qt、C++、嵌入式、ESP32、FreeRTOS、通信协议、前端、JavaScript、Vue、React、Git、数据库、Docker、Linux、深度学习、数据结构、算法、计算机组成原理、学习方法、个人成长、产品设计。

共 24 个主题，每篇最多 3 个，不因为只出现一次就删除真正的主要技术主题。

## 归并与剔除

- `ai / AI` → 人工智能。
- `Agent SDK / Multi-Agent / Tool Use / MCP` → AI Agent。
- `ESP32-S3 / ESP-IDF` → ESP32；物联网主题归为嵌入式。
- `Vue2 / Vue3 / VueCli / Vuex` → Vue。
- `SQL / MySQL / SQLite` → 数据库，便于关联 MySQL 笔记和 Qt SQLite 笔记。
- 教程、实践、指南、原理、基础原理、导航、第一个程序等形式和泛词不进入标签。
- `QWidget / QTimer / Q_PROPERTY / QHBoxLayout` 等实现细节不进入标签。
- 少见的主要主题可以保留，例如 React；不按使用次数机械删除。

## 生效位置

`src/utils/post-tags.ts` 维护主题和归并关系，`src/content.config.ts` 在文章载入时统一应用。文章页、标签页、归档筛选、统计与相关推荐均消费同一份规范化后的数据。

源稿原有关键词不批量重写，文章正文和分类不修改。同步脚本重新拉取内容时仍会经过这份规则，不会重新生成细碎的可见标签。

新增主题时先考虑是否能归入现有主题；确实需要新的主要领域或技术，再扩展主题表。没有识别到主题的文章可以没有标签，不把标题或任意新分类自动升级为标签。
