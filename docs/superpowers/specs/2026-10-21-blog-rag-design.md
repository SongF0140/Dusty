# 博客文章级 RAG

用户已确认采用“先检索相关文章，再读取全文回答”的轻量方案。

## 已确认范围

- 复用 Pagefind 全文检索和现有 terminal-posts Markdown 全文接口，不增加向量数据库。
- 构建时导出公开文章目录：文章 ID、标题、站内链接、摘要、标签、分类、发布日期、更新时间和全文接口地址。
- 草稿和密码文章始终排除，包括开发环境。
- 查询时按 Pagefind 排名匹配目录中的博文，去重后最多读取三篇全文。非博文结果不进入上下文。
- 上下文带文章标题、链接与日期。无匹配结果返回空证据，不补充随机文章。
- 读取失败明确报错，不将失败误报为无匹配。上下文按字符预算限制，超长文章明确列出，不静默截断全文。
- 保留现有搜索界面，海问香助手接入发送与回答，保留草稿和本地对话存储。

## 模型与部署（已由用户确认）

使用 OpenAI 兼容 Chat Completions 接口，根地址、模型 ID、Key 通过服务端环境变量配置。网站部署在 Vercel，根目录 `api/blog-chat.ts` 承载模型调用。构建时生成的公开文章快照随函数打包，不依赖生产域名回源或客户端提供的文章正文。API Key 不进入浏览器。文章正文是参考资料，不具备系统指令权限。

没有配置时只允许草稿；配置可用时开启发送。调用失败保留问题草稿。浏览器仅渲染文本与站内博文链接，刷新恢复对话。当前采用非流式回答，48000 字符上下文预算和 45 秒上游超时。

## 人设与回答边界（用户追加确认）

允许寒暄和引导阅读。知识回答优先依据博客，扩展内容必须标注“【扩展说明】”，不冒充作者观点。不提供外部链接，仅保留公开目录中的站内博文链接。无博文证据的知识问题仍可请求模型，服务端在回答前明确说明未检索到相关博文并加扩展标记；纯寒暄和阅读引导不强加知识扩展标签。阅读引导可参考部分公开目录元数据，不冒充已阅读相应正文。

前后端共享输出处理，去除外部 Markdown/HTML 链接、裸网址、参考链接定义和未知站内文章链接。语气温柔沉静、自然简洁，技术准确性优先。

## 验收

测试公开目录过滤、中英文与编码 URL 匹配、结果去重和排名、全文读取上限、空结果、网络错误和预算不足。检查 Astro 路由生成与类型检查。模型端到端问答要在接口确定并配置后验证。
