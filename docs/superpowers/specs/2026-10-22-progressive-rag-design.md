# 渐进式 RAG 与文章摘要

用户授权实现 RAG 切分、内容更新，以及标题下复用海问香逐字效果的摘要；并明确选择模型生成摘要，正文变化后重新生成。

采用三层披露：搜索只返回标题、简介及章节概览；读取时先看目录，再用问题召回章节片段；只有显式请求才读取全文。工具仍限定 search_posts、read_post、list_categories，read_post 增加层级参数。按 Markdown 标题与段落切分，代码围栏中的标题不作为分界；大段按上限继续拆分，保留少量上下文重叠。关键词/BM25 检索适用于当前小规模公开博文，不引入向量数据库。

StarryLin 的纯 RAG 模块为实现源，导出副本进入博客，避免 Vercel 依赖部署目录之外的文件。分块索引用不承担安全校验的内容版本标识，模型摘要缓存用 SHA-256 校验；重新构建替换当前公开目录，删除、草稿、加密文章退出索引。文章页、简介与检索目录共享 content collection 的 description。

用户随后明确要求现有简介保持，先存入 SQL，以后正文变化才重建。首次将原始简介和正文 SHA-256 存入 blog_post_summaries；仅正文变化后通过兼容接口生成新摘要，模型或标题变化不触发重写。记录区分 manual/model，长文按块概括再合并。已配置 Neon 时共享状态，无数据库时用本地磁盘基准。没有模型配置或生成失败不推进旧基准；不在访客打开文章时请求模型。当前 123 篇公开博文已导出为可重复执行、不覆盖已有行的初始化 SQL；未连接真实 Neon。

标题下摘要用自定义元素逐字显示，沿用海问香的速度、停顿与光标形式，适配窄屏、Swup 重入、减少动态效果和无 JavaScript 的完整正文。播放一次后保留完整摘要，不循环删除；不对屏幕阅读器逐字播报。

本次不包含队列调度、GitHub OAuth 或正式部署，不改动现有文章插图工作。
